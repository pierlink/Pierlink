Pierlink 1.2.17

几处使用上的小修正。在程序里检查更新即可升级。

- **下载更新不再挡住窗口**：下载进度、下载好了、出错都显示在右下角的更新卡片上，下载期间照常使用；只有点了“安装更新”、程序马上要关闭时才弹出提示。
- 标签右键“复制标签”：新标签紧跟在被复制的标签后面，不再排到最后。
- 程序接管了鼠标（部分 AI 命令行会这样）时直接拖动选不中文字：这时拖一下，终端上方会提示“按住 Shift 拖动可选中文字”。
- AI 客户端列表里的 Antigravity 写成“Antigravity / agy”：Antigravity 的桌面端、IDE 和命令行 agy 共用一份配置，添加一次都生效。
- 修复：终端里的程序开了鼠标模式时，鼠标在终端上移动或点一下，AI 之后每次回车都会弹出“终端里可能有还没回车的文字”的确认。鼠标的移动和点击不再算作你打了字。
- 修复：窗口宽度凑巧时，终端最右一列被右边缘切掉一两个像素（靠右对齐的状态栏最后一个字显示不全），滚动条还会压住最右边的字。现在终端右侧给滚动条单独留了位置。
- 修复：程序被强行结束或终端里的 ssh 断开后，鼠标模式留在提示符上（鼠标一动提示符上就多出一串数字，拖动也选不中文字）。服务器的 bash、zsh 和本机 Git Bash 回到提示符时会自动关掉它。
- 修复：拖动分屏分隔条时窗口被别的程序抢到前台，窗格可能一直点不动。

Pierlink 1.2.17 (English)

A few small usability fixes. Update inside the app.

- **Downloading an update no longer blocks the window**: progress, completion and errors are shown on the update card in the bottom-right corner, and you can keep working while it downloads. A dialog appears only after you click "Install update", when the app is about to close.
- "Duplicate tab" in the tab menu puts the new tab right after the one you duplicated instead of at the end.
- When a program takes over the mouse (some AI command-line tools do), dragging does not select text. Dragging now shows a hint above the terminal: hold Shift and drag to select.
- Antigravity in the AI client list is now labelled "Antigravity / agy": the Antigravity desktop app, IDE and the agy command line share one configuration, so adding it once covers all of them.
- Fixed: when a program in the terminal had mouse mode on, moving the mouse over the terminal or clicking it made every later Enter from AI ask for confirmation ("the terminal may contain text that has not been submitted"). Mouse movement and clicks no longer count as you typing.
- Fixed: at some window widths the rightmost terminal column was cut off by a pixel or two (the last character of a right-aligned status line looked incomplete), and the scrollbar covered the rightmost characters. The terminal now reserves room for the scrollbar on the right.
- Fixed: after a program was killed or an ssh session inside the terminal dropped, mouse mode stayed on at the prompt (moving the mouse typed a string of numbers, and dragging did not select text). bash and zsh on servers and Git Bash on this PC now turn it off when the prompt comes back.
- Fixed: if another program took the foreground while you were dragging a split divider, panes could stay unclickable.
