Pierlink 1.2.6

同步失败的文件能看到服务器上的了，没有权限的可以直接修复；还能打开服务器的 Syncthing 管理页。在程序里检查更新即可升级。

- 改进：新建同步任务的默认排除规则加上常见的、同步过去没用的文件：IDE 配置（.idea、.vs）、Python 虚拟环境和生成物（venv、.tox、*.pyc、*.egg-info、.ipynb_checkpoints）、前端构建缓存（.next、.nuxt、.svelte-kit、.turbo、.parcel-cache、.eslintcache）、.gradle、vim 交换文件（*.swp、*.swo）、.DS_Store。设置里的默认排除规则没改过的，会自动换成新的；改过的不变。已有的任务不变，需要的话在“编辑任务”里加。
- 新功能：同步失败的文件里也列出服务器上失败的，每行写明是本机还是哪台服务器。
- 新功能：本机因为没有权限同步失败的文件，可以点“修复权限”，在 Windows 的管理员确认后修好；服务器上没有权限的，可以复制修复命令到服务器的终端里运行。
- 新功能：同步任务里可以打开服务器的 Syncthing 管理页，查看服务器上的同步详情。关掉后，在里面改过的设置会改回 Pierlink 的设置。
- 改进：AI 要你确认的操作没人回应时，会说明确认框在哪台电脑上；AI 看到的 Windows 也带上了电脑名。几台电脑都开着 Pierlink 时，不会再找不到确认框。
- 改进：同步任务的打开按钮默认在资源管理器里打开文件夹，装了 Cursor、VS Code 也一样。在下拉里选过编辑器后，这个任务默认用它；再选“文件夹”就改回来。
- 修复：网络连上了但 GitHub 不回应时，检查更新一直停在“正在检查…”，按钮也点不了；现在最多等 15 秒。
- 修复：检查更新失败时提示太长，显示不全。
- 修复：服务器上改的文件同步到本机后，最近事件里过一会儿又多出一条同一文件的“本机→服务器”，看起来像被传了回去。其实没有传，现在不再显示。

Pierlink 1.2.6 (English)

Failed files now show the ones on servers too, permission problems can be fixed in place, and a server's Syncthing admin page can be opened. Update inside the app.

- Improved: the default exclusion rules for new sync tasks now cover common files that are useless on the other side: IDE settings (.idea, .vs), Python environments and build output (venv, .tox, *.pyc, *.egg-info, .ipynb_checkpoints), front-end build caches (.next, .nuxt, .svelte-kit, .turbo, .parcel-cache, .eslintcache), .gradle, vim swap files (*.swp, *.swo) and .DS_Store. Default rules in Settings that were never edited switch to the new list; edited ones stay as they are. Existing tasks are unchanged; add the rules in Edit task if needed.
- New: failed files now include those that failed on the servers, and each row says whether it was this PC or which server.
- New: files that failed on this PC for lack of permission can be fixed with "Fix permissions" after Windows asks for administrator approval; for permission failures on a server, copy the fix command and run it in that server's terminal.
- New: a sync task can open a server's Syncthing admin page to see its sync details. After it is closed, settings changed there are put back to Pierlink's.
- Improved: when an AI's request for your confirmation gets no answer, it now says which computer the confirmation is on, and the Windows target the AI sees carries the computer name. With Pierlink open on several computers, you no longer miss the confirmation.
- Improved: the open button of a sync task now opens the folder in File Explorer by default, even with Cursor or VS Code installed. After you pick an editor from its menu, that task uses it by default; pick "Folder" to switch back.
- Fixed: when the network was up but GitHub did not answer, the update check stayed on "Checking…" and the button could not be clicked; it now gives up after 15 seconds.
- Fixed: the message for a failed update check was too long to show in full.
- Fixed: after a file changed on the server synced to this computer, recent events later showed an extra "PC → server" entry for the same file, as if it had been sent back. Nothing was sent; the entry no longer appears.
