Pierlink 0.9.0

- AI 跑在服务器上，像装在 Windows 上一样干活：Windows 不用装 Claude Code，服务器上的 AI 经 Pierlink 就能
  - 按行读、只改几行、按内容搜索、按文件名查找你允许的 Windows 文件夹，文件的编码和换行原样保留（GBK、UTF-16、CRLF 都行）；
  - 在 Windows 上选 shell 执行命令、开后台任务（开发服务器等）、随时看输出和结束；
  - 查到自己能在哪些文件夹干活、可用的 shell、同步的服务器路径对应 Windows 哪里；怎么做由 AI 自己决定；
  - 超过 60 秒的编译、等同步不再被中途掐断。
- 服务器上的 Gemini CLI 也能一键接上；手动接入命令改成用户级，换令牌后不用先删再加。
- 标题栏的“最近操作”可以点开看命令输出。
- 终端里 Shift+Enter、Ctrl+Enter 和常用终端一样是换行、不会提交（screen、tmux 里的 Claude Code，本机 Git Bash、WSL 也一样）；本机 PowerShell、命令提示符按它们自己的原生规则处理。
- 服务器桌面：服务器上没有桌面时可以一键新建（只有你能连，关掉标签后继续运行）；缺 TigerVNC 时自动获取，不需要管理员权限；可以“关闭桌面”结束它。
- 修复：AI 读写文件时，Windows 网络共享路径会在检查授权范围之前被打开。
- 修复：服务器桌面关掉“远程分辨率跟随窗口”、断开或关掉标签后，远程分辨率不会改回原来的大小。

Pierlink 0.9.0 (English)

- An AI on a server works as if it were installed on Windows: no Claude Code on Windows needed. Through Pierlink, the server-side AI can
  - read by line, edit just a few lines, search by content and find by name in the Windows folders you allow, keeping file encodings and line endings as they are (GBK, UTF-16, CRLF);
  - run commands on Windows in a shell of its choice, start background tasks (dev servers and the like), check their output and stop them;
  - see which folders it may use, which shells exist, and where a synced server path lives on Windows; how to use that is up to the AI;
  - keep builds and sync waits running past 60 seconds instead of being cut off.
- Gemini CLI on a server can be connected in one click; the manual setup command now uses user scope, so a new token no longer needs a remove first.
- Recent activity in the title bar can show a command's output.
- In a terminal, Shift+Enter and Ctrl+Enter insert a new line instead of submitting, as in common terminals (including Claude Code inside screen or tmux, and local Git Bash or WSL); local PowerShell and Command Prompt handle them by their own native rules.
- Server desktop: create a desktop when the server has none (only you can connect, and it keeps running after you close the tab); TigerVNC is fetched automatically without admin rights; "Close desktop" ends it.
- Fix: a Windows network share path could be opened before the authorized-folder check when an AI read or wrote files.
- Fix: the server desktop kept the window-matched resolution after turning that option off, disconnecting or closing the tab.
