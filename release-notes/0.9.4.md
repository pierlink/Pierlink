Pierlink 0.9.4

这一版专门修 AI 接入（MCP）自检发现的问题：

- 确认框 60 秒没人点，不再被当成“拒绝”：AI 下次调用会重新询问（以前要点“全部停止”才能恢复）。只有点了“拒绝”才会记住。
- 一键添加到 Codex 时写入 30 分钟的工具超时（Codex 默认 60 秒就放弃，长一点的编译、测试会被提前截断）；换令牌后，一键添加过的 Gemini CLI 也会自动用新令牌重加。
- 服务器上的 AI 空闲一会儿后再调用，不再报连接错误（影响 Gemini CLI 和旧版 Claude Code）。
- AI 终端：发命令后能稳定等到输出；在 Windows 终端里以换行结尾的命令也会执行；终端程序的自动应答不再触发“实际执行的内容未知”的确认框。
- 在授权的文件夹里改 .js、.py、.sh 等源码不再每次弹确认；.ps1、.bat、快捷方式这类双击就会执行的文件仍要确认。
- Windows 上执行命令返回真实的退出码（以前只有 0 和 1）。
- 安全修复：AI 打开本机终端时，目录名里的弯引号可能被当成命令执行。
- 给 AI 的报错会说明是哪个参数不对；后台任务、同步等待的返回更完整；本机手动添加命令改为对所有项目生效；服务器入口详情里显示地址文件是否已写到服务器上。

Pierlink 0.9.4 (English)

This release fixes what a self-check of AI access (MCP) turned up:

- A confirmation nobody answers within 60 seconds no longer counts as "Deny": the AI is asked again on its next call (it used to take Stop all to recover). Only an explicit Deny is remembered.
- One-click add to Codex sets a 30-minute tool timeout (Codex gives up after 60 seconds by default, cutting longer builds and tests short); after rotating a token, Gemini CLI setups are redone with the new token too.
- AI on a server no longer gets a connection error when it calls again after being idle for a while (affected Gemini CLI and older Claude Code).
- AI terminals: waiting for a command's output after sending it works reliably; commands ending in a newline also run in Windows terminals; terminal programs' automatic replies no longer trigger the "actual input unknown" confirmation.
- Editing .js, .py, .sh and other source files in an authorized folder no longer asks every time; files that run on double-click, such as .ps1, .bat and shortcuts, still ask.
- Commands on Windows return the real exit code (it used to be only 0 or 1).
- Security fix: when the AI opened a local terminal, curly quotes in the folder name could be run as a command.
- Errors to the AI name the parameter that is wrong; background jobs and sync waits return more detail; the manual add command for this PC now applies to all projects; a server entry's details show whether its address file has been written on the server.
